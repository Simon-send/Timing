# Athlete seasons and result eligibility

The profile result list and its analysis share one `AthleteSeasonDataset`, built from the full `watchAthleteRaces` repository stream before presentation paging. Available seasons are derived from event metadata for actual results. The existing repository queries both legacy and stage result collections without a result limit; tests cover more than 200 rows and stream disposal.

`seasonFor` is the central sport rule. Cross-country skiing and biathlon use May 1 through April 30 inclusive; a start year of 2025 displays as 2025/26. Unknown sports or dates have no inferred season. Unassigned rows remain visibly labelled in the list; they do not contribute to a specifically selected season's statistics. All-seasons includes them without assigning a season. Multiple selection uses the union of selected seasons.

`AthleteSeasonScope.races` supplies visible rows, including non-finish statuses. `statisticalRaces` supplies analyses and requires a completed result in the selected scope. Dart `result_status.dart` and importer `result-status.js` share the exclusion policy: DNF, DNS, DFQ, DSQ/DQ and existing non-classified aliases never contribute, even with valid partial splits. Missing measurements stay missing. Relay-leg derivation preserves a non-finishing team status. New analyses in tasks #9–#12 must reuse this scope and status contract.

History metrics report their own valid-point count; the selector distinguishes visible and completed races. Per-race reference comparisons retain their existing semantics. Raw finish and ski times are not pooled across distances or programs.

Shooting selection uses `ShootingMetric` and `ShootingSelection` in `shooting_selection.dart`. `AthleteRace.shootingSelection` supplies per-pass observations only for completed races in the caller's season scope; `validObservations` retains measured values and valid zero misses. Missing data stays null. Numbered selections sort by source index and count within known positions; earlier gaps, duplicate indices or unknown positions make that ordinal unavailable. Unnumbered selections can still expose known measurements. Importer reference-profile pass indices remain global indices and are not relabelled as position ordinals.

The same controls appear in race details and the season overview. Relay range times remain selectable, but hits and shot misses are unavailable because the current public data does not distinguish reserve shots from penalty loops. Whole-team relay positions are unavailable because the importer can synthesize them from global indices; All shootings retains their range times with unknown positions. Persisted per-leg analysis keeps known locally scoped positions. Legacy fallback retains the measured range times and global indices, but clears synthesized whole-team positions; those fallback series cannot support position or ordinal selection. The importer schema is unchanged.

`calculateSeasonShootingStatistics` is the pure calculation contract for tasks #10–#12. Pass it the full selected scope's races and a `ShootingSelection`. It excludes whole non-finishers again before selecting raw series. Each metric retains its race, source series index, position and nullable value for later distributions and navigation. Valid zero misses contribute five hits; invalid or missing misses contribute neither hits nor shots. Pooled hit percentage is total known hits / (five shots per validated individual series), never an average of race percentages or a reconstruction from stored percentages. Otherwise completed races may contribute their valid individual series even when other series are missing.

Average misses and mean/median range times use their own valid series. Per-metric valid/missing counts cover only recorded, selectable series; absent series and uncertain order do not create guessed slots. `unavailableRaces` separately identifies races without any selectable recorded series. A race with a partial set of recorded series still exposes the selection's existing incomplete-data warning. Relay series may contribute range times while all their hit/miss measurements remain unavailable. Empty metrics return null, including percentages when only old rounded percentages exist.

The season overview opts into this summary through `ShootingSelectionPanel.statisticsRaces`; its shooting selection updates all four summary metrics while the metric control selects the distribution and per-race observation rows. Race details keep their existing view. The obsolete unweighted season hit-percentage card has been removed from the reference-comparison panel.

`SeasonShootingDistribution.fromStatistics` bins the selected metric's valid series, retaining the original race, source index, position and value. Hits/misses always have six discrete bins, 0–5. Time boundaries are integer milliseconds aligned to seconds; intervals include the lower edge and exclude the upper edge, except the last interval includes both. An explicit `ShootingDistributionScale` can be constructed from a union of samples for common bins; a mismatched metric or uncovered observation is rejected rather than silently dropped. `HistogramBarsPainter` and `HistogramChartLayout` supply the same bars, axes, colors and hit geometry to result and season charts; existing result percentile/regression/split defaults remain unchanged. The season chart and keyboard-accessible table show counts and percentages of measured series, with mean, median, n and a warning below five series. Bin contributions use supplied event labels and a navigation callback with event/class/result/stage identity and a relay leg when known; widgets perform no queries or membership inference.

The importer now applies the same status policy to class ranking and biathlon all/top-half cohorts. No production import, reimport, deployment or data rewrite is performed by this change. Previously materialized reference profiles are not rewritten by a client update; validating/rebuilding affected old profiles requires a separately authorized import operation. The additive UI feature and tests use synthetic input and existing read contracts.

The repository delegates combined live-query processing with `yield* ...asyncMap` so cancelling a profile subscription propagates to its underlying queries. The full-history repository test awaits subscription disposal; the previous `await for`/`yield` loop stalled that disposal in the test and the delegation completes it.

When an individual source declares a different recorded shooting count from the expected class count, its inferred positions are unassigned in the selection series. All measurements remain usable; positional selections cannot pool contradictory source classifications. This does not rewrite historical importer data or stored reference profiles.

Season comparison (#12) takes the complete dataset even when the profile display selects one season. `SeasonComparisonDataset` requires a known biathlon sport/date and an unambiguous explicit program. The repository carries class `ResultClass.name` and `ResultClass.etappeName` from its existing parent-class reads into `AthleteRace.programLabels`; the resolver recognizes program words, never age, distance, series count or event title. An unambiguous `ResultEvent.disciplines` value is a fallback when class program metadata is absent. Multiple class programs, conflicting event disciplines and relay/individual disagreement are excluded visibly. Explicit class programs may disambiguate a multi-program event when that event includes the selected program. No extra queries or writes are introduced.

Comparison validates historical inferred positions against the explicit program: sprint P,S and pursuit/mass start P,P,S,S. It does not invent absent positions. Normal/short individual and variable supersprint formats cannot establish their positions from the historical count-based mapping, so position selections are unavailable and All keeps measured series with unknown positions. Relay safeguards remain those of the shared shooting-selection contract. `calculateSeasonShootingStatistics` accepts a comparison observation selector while retaining its status, measurement and contribution accounting. Shared union bins and exact percentage/count heights use one common maximum in both panes. Delta is B minus A: hit rate in percentage points, mean range time in seconds, mean misses per series. The UI explains sample/condition limitations and provides the existing accessible contribution table and result navigation.

Supersprint does not establish five-shot hit/miss counts from penalty additions: reserve-shot semantics are not recorded. Comparison therefore leaves hits, misses and the shot denominator unavailable for that program, while keeping measured stand times.
